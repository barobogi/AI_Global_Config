## 1. 경쟁앱 5종 Deep Search 요약

| 앱 | 핵심 킬러 기능 | 오늘뭐하지에 줄 시사점 |
|---|---|---|
| **트리플** | AI 일정 생성, 동행자 초대해 함께 계획, 코스 공유/경비 정산, 도시가이드 | 코스를 "혼자 보는 결과"가 아니라 "같이 보고 공유하는 것"으로 |
| **데이트팝** | 위치기반 데이트코스 추천, 실시간 리뷰, 구독형 딜(팝패스) | 동행자=연인일 때 특화된 톤/추천 로직 필요 |
| **캐치테이블** | 조건조합 실시간 검색(지역+편의시설+목적), 빈자리 알림, 웨이팅 미루기 | "지금 가면 바로 되는지" 실시간성이 만족도를 좌우 |
| **핫플가이드** | 스마트어라운드(반경 슬라이더+시간대/성별/음식종류 필터), 실판매량 기반 인기메뉴 순위 | 반경/조건을 결과 화면에서 바로 재조정하는 UX |
| **마이리얼트립** | 과거 이력 기반 초개인화 추천, 빠른 반응형 UI(로딩 1.7초 단축) | 동행자 타입별 가중치 자동 조정 |

**공통 패턴**: 5개 앱 모두 (1) 조건을 결과 화면에서 즉시 재조정 가능, (2) 동행자/상황별로 추천 로직 자체가 달라짐, (3) 공유·소셜 요소가 있음. "오늘뭐하지"는 이 3가지가 약함 — 현재는 조건입력→결과가 1회성이고, 동행자는 "아이 동반 여부" 정도만 반영.

## 2. 도입 제안 TOP 5

### ① 동행자 타입별 가중치 프리셋 (마이리얼트립·데이트팝 영감)
- **내용**: 동행자를 "연인/가족(아이동반)/친구/혼자" 4종으로 세분화, 각 타입마다 `score_engine.py`의 `weights` dict를 다르게 적용 (예: 연인→weather_fit·novelty↑, 가족→distance_score·budget_fit↑, 혼자→time_fit↑)
- **기존 로직과의 결합**: `ScoreEngine.__init__`의 `self.weights`를 고정값 대신 `companion_type` 인자 받아 프리셋 딕셔너리에서 선택하도록 확장. 하드필터/장소 데이터 구조는 그대로.
- **난이도**: 중 (백엔드 로직 확장 + Android ConditionInputScreen에 동행자 타입 선택 UI 추가)

### ② 반경 슬라이더 + 결과 화면 즉시 재조정 (핫플가이드 영감)
- **내용**: ResultScreen에 반경(1/3/5/10km) 슬라이더 배치, 조정 시 조건입력 화면으로 안 돌아가고 바로 재필터링
- **기존 로직과의 결합**: `hard_filter.py`의 `check_distance()`가 이미 있어 백엔드 변경 거의 없음 — API에 `max_distance_km` 파라미터로 재호출만 하면 됨
- **난이도**: 하

### ③ 코스 공유 카드 (트리플 영감)
- **내용**: 추천받은 3코스 중 하나를 카카오톡/링크로 공유 가능한 카드 이미지로 생성
- **기존 로직과의 결합**: 완전 신규 기능이지만 백엔드 추천 결과(장소명/이유/지도좌표)는 이미 존재 — 이미지 렌더링(Compose Canvas 또는 이미지 조합) + 카카오 공유 SDK만 추가
- **난이도**: 중

### ④ "지금 가기 좋음" 실시간 배지 (캐치테이블 영감)
- **내용**: 영업 마감 임박(1시간 이내)이면 "곧 마감" 경고 배지, 방금 열었으면 "지금 한산할 가능성" 배지
- **기존 로직과의 결합**: `hard_filter.py`의 `check_is_open()`이 이미 영업시간 판정하고 있어, 마감까지 남은 시간만 추가 계산하면 됨 — 공공데이터라 실시간 혼잡도는 불가하므로 "시간대 기반 추정"으로 명확히 표기
- **난이도**: 하

### ⑤ 인기도 시각 배지 (핫플가이드·데이트팝 영감)
- **내용**: `score_engine.py`의 `popularity`(가중치 0.10) 점수를 ResultScreen 카드에 "이번 주 인기" 같은 배지로 시각화
- **기존 로직과의 결합**: 백엔드 변경 전혀 없음, 이미 계산되는 점수를 UI에 노출만 하면 됨
- **난이도**: 하 (가장 빠르게 적용 가능, 우선순위 1순위 추천)

## 4. 검토 필요 사항 (코니 Auditor 확인 요청)
- ① 동행자 타입별 가중치 수치는 임의 설정값 — 실사용자 데이터 없이 감으로 정한 것이라 UX 관점 타당성 검토 필요
