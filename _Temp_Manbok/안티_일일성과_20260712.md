## 1. 💡 기획 및 설계 단계
유튜브 자동 제작 파이프라인의 안전 통제를 위해 n8n `Wait for Approval` 노드에 **24시간 타임아웃 자동 반려 기능**을 결합하는 고도화 설계를 진행했습니다.
* **텔레그램 자동 편집**: 타임아웃 발생 시, 텔레그램 API를 호출하여 기존 메시지의 인라인 버튼(승인/반려)을 즉시 지우고, 메시지 본문을 `🔴 [승인 대기 시간 초과] 이 요청은 24시간 내에 응답이 없어 자동 반려되었습니다.` 상태로 업데이트하도록 `send_approval.py --edit-timeout` 명령을 코딩했습니다.
* **비대칭 흐름 격리 설계**: 타임아웃으로 강제 재개 시 웹훅 호출 컨텍스트(HTTP Request)가 존재하지 않아 `Respond to Webhook` 노드에서 크래시가 발생하는 n8n 엔진의 특성을 파악, **수동 반려(웹훅 응답 처리)**와 **자동 반려(웹훅 없이 즉각 텔레그램 편집)** 분기 경로를 완벽히 격리하여 라우팅 설계했습니다.

## 2. 🛠️ 트러블 슈팅 (3대 난제 해결 과정)

E2E 검증 과정에서 발생한 복잡한 n8n 엔진과 SQLite 데이터베이스 간의 충돌 및 문법 오류들을 완벽하게 디버깅하여 해결했습니다.

### ① SQLite `SQLITE_ERROR: no such column: NaN` 크래시 해결
* **원인**: SQLite를 백엔드로 쓰는 n8n에서 대기 웹훅 경로에 영문자가 포함될 경우 (`t020-resume-6618`), n8n 내부에서 재개 웹훅 호출 시 해당 경로의 ID를 파싱하다가 숫자가 아닌 값으로 처리되어 `NaN` 예외를 유발했습니다. SQLite가 이를 조회 컬럼명으로 인식하여 `WHERE id = NaN`으로 쿼리를 수행하며 n8n 전체가 500 에러로 다운되었습니다.
* **해결**: 대기 웹훅 경로를 순수 숫자형 변수값인 `={{$executionId}}`로 변경하여 SQLite 호환을 완전히 맞췄습니다. (예: `.../webhook-waiting/6639`)

### ② Webhook HTTP Method (404 Not Found) 오류 해결
* **원인**: n8n Wait 노드는 기본 수신 방식으로 `GET`만 활성화되어 있어, 로컬 봇 데몬이 POST 본문으로 승인/반려 페이로드를 전달할 때 매칭 실패로 404 에러가 났습니다.
* **해결**: 워크플로우 템플릿의 파라미터 내부에 `"httpMethod": "POST"` 설정을 명시적으로 강제 주입하여 POST 요청을 정상 처리하도록 수정했습니다.

### ③ n8n Expression `stdout` String JSON 파싱 오류 해결
* **원인**: `Send Approval Request` 노드의 `stdout` 출력이 JSON 객체가 아닌 raw string 형태였기에, 타임아웃 액션 노드에서 `$('Send Approval Request').item.json.chat_id` 등의 환경 변수를 직접 참조 시 빈 문자열(`""`)로 치환되어 봇 API 호출이 에러로 실패했습니다.
* **해결**: n8n 수식 내부에서 `JSON.parse` 함수를 이용해 문자열을 객체로 변환하여 참조하도록 명령줄을 개선했습니다:
  `{{ JSON.parse($('Send Approval Request').item.json.stdout).chat_id }}`
