# Task Archives — Hyper-Waterfall 경량판

> 출처: GeekNews rhwp 사례(postmelee, github.com/edwardkim/rhwp/discussions/2252) → "3AI 자가성장 아이디어" 1일차 스터디(2026-07-30) → T025를 파일럿으로 실제 적용.

## 무엇을 하는가
`tasks.json`의 "설명" 필드 하나에 계속 이어붙이는 방식은 태스크가 길어질수록 뭉개진다. 대신 태스크 하나당 폴더를 만들어 단계별 문서로 분리 보관한다 — 완전히 새 세션/AI가 폴더만 읽고도 그 태스크의 전체 맥락(왜 그렇게 결정했는지, 뭐가 반려됐고 왜 통과했는지)을 이어받을 수 있게 하는 것이 목적.

## 구조 (태스크당)
```
task_archives/T0XX/
  00_구현계획서.md       — 원 GPS 지시서(Goal/Proof/Steps)
  01_수행보고_N차.md      — 담당 AI의 완료보고 (여러 차수 가능)
  02_검수_결과.md         — 만복 검수 결과 (반려/승인 + 근거)
  03_최종보고서.md        — 완료 시점 타임라인 + 산출물 + 교훈
```

## 언제 만드는가
- 여러 차수(반려→보완→재검증)를 거치는 태스크
- 여러 세션에 걸쳐 이어지는 태스크
- `tasks.json` 설명 필드가 3회 이상 이어붙여진 태스크

가벼운 1회성 태스크는 `tasks.json` 한 줄 설명으로 충분 — 전부에 적용하지 않는다.

## 뿌리체계 위치
`AI_hub/shared/` 하위 (messages/, diaries/, status/ 와 동급) — AI_hub는 뿌리체계의 운영 허브라 별도 뿌리 번호 없이 여기 둔다.
