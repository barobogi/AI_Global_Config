안티야, 코니 PASS 받고 제가 최종 검증하다가 하나 더 찾았어. keystore 재발급 + 파일 git 제거까지는 잘했는데, **비밀번호 문자열이 여전히 공개 저장소에 하드코딩돼있어서** 새로 판 키도 사실상 노출된 것과 같은 상태다.

## 발견한 문제
`65_android_apps/today_what_to_do/android/app/build.gradle.kts` 26/28행:
```kotlin
storePassword = System.getenv("KEYSTORE_PASSWORD") ?: "today1234"
keyPassword = System.getenv("KEY_PASSWORD") ?: "today1234"
```
`KEYSTORE_PASSWORD`/`KEY_PASSWORD` 환경변수를 어디서도 설정 안 하고 있는 걸 확인함(`local.properties`, `.env` 둘 다 없음) — 즉 지금 실제 빌드는 fallback인 `"today1234"`로 서명되고 있고, 이 문자열이 그대로 git에 커밋돼서 public 저장소에 올라가있음. 새 keystore(ac28fcb3...)도 결국 같은 약한 비밀번호로 보호되는 셈이라, 키 재발급의 실효성이 없어진 상태.

## Goal
비밀번호를 소스코드에서 완전히 제거하고, 실제 빌드가 그 비밀번호를 gitignore 대상 파일에서만 읽도록 수정.

## Proof (완료 기준)
1. `build.gradle.kts`에 비밀번호 리터럴("today1234" 등) 완전히 삭제 — grep으로 재확인 가능해야 함
2. `local.properties`(이미 `.gitignore` 대상 확인함)에 `KEYSTORE_PASSWORD=...`, `KEY_PASSWORD=...` 형태로 실제 값 저장, `build.gradle.kts`는 여기서 읽도록 수정
3. 값이 없으면 **조용히 fallback 쓰지 말고 빌드 자체가 실패**하게 처리 (예: `?: error("KEYSTORE_PASSWORD not set")`) — 이번처럼 "설정 안 해도 그냥 예전 값으로 돌아가는" 구조가 문제였음
4. 수정 후 release APK 재빌드 → 서명 정상 확인(키 alias `todaywhattodo`, 새 시리얼 `ac28fcb3...` 유지되는지) 스크린샷 또는 로그 첨부

## 참고
- 완료보고 자동검증 우선 원칙 적용 대상 — 위 4번 실행 로그 꼭 첨부해줘.
- 급하지만 서두르다 또 구멍 나면 다시 반려되니, 이번엔 "비밀번호가 소스 어디에도 문자열로 안 남아있는지" 본인이 먼저 grep으로 확인하고 보내줘.

이거 고치면 바로 최종 승인하고 바로보기님께 Play Store 등록 진행하시라고 전달할게.
