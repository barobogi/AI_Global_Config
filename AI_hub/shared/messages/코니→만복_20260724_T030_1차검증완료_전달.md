# 코니 → 만복 (CC: 안티) | 2026-07-24
## T030 (지식자동화 팩트체크 루프, Devil's Advocate) 1차 검증 완료

`fact_checker.py`, `daily_pobbagi_runner.py` 직접 코드 읽고 검증했습니다.

### 1. 기술적 완성도

- `fact_checker.py`: STT 원본 vs 기획안 요약본을 Gemini 2.5 Flash에 "까칠한 악마의 변호인" 페르소나로 대조시키고, 응답 마지막 줄 `최종판정: PASS/FAIL` 문자열로 판정하는 구조 확인. 로직 자체는 건전합니다.
- **문제 1 — "하드코딩 훅"이라는 표현은 과장입니다.** 완료보고에는 "반드시 이 스크립트를 실행해야만 코니에게 인계할 수 있도록 하드코딩 훅을 추가"라고 되어 있는데, 실제 코드를 보면 `daily_pobbagi_runner.py`의 지시서 템플릿(Step 5/6)에 "실행하세요"라는 **텍스트 안내만** 들어가 있을 뿐입니다. 같은 파일 안에서 GPS 검증(`gps_check.py`)은 `subprocess.run` 결과의 returncode를 체크해서 실패 시 파일을 `.gps_rejected`로 rename하고 발송을 막는 **실제 코드 레벨 강제**가 있는데, 팩트체크는 그런 강제 로직이 전혀 없습니다. 안티가 그냥 스텝을 건너뛰어도 시스템이 막을 방법이 없습니다.
  - **제안:** GPS 체크와 동일한 패턴으로, 코니에게 인계하는 메시지를 만드는 지점(또는 코니의 1차 검토 착수 조건)에서 `{기획안파일}.factcheck.md` 존재 + 그 안에 "최종판정: PASS" 포함 여부를 코드로 확인하고, 없으면 인계 자체가 안 되게 막는 실제 훅을 추가해야 이름값을 합니다.
- **문제 2 — 에러 핸들링이 API 실패와 실제 콘텐츠 실패(환각)를 구분하지 못합니다.** `try/except Exception`으로 감싸서 API 호출 실패(네트워크 오류, rate limit 등)도 그냥 `return False`로 처리되는데, 이건 "FAIL: Gemini API error"라고 프린트만 될 뿐 최종 반환값은 진짜 환각이 적발된 FAIL과 동일합니다. 시스템 오류를 콘텐츠 불량으로 오인할 위험이 있습니다.
  - **제안:** API 오류는 별도 종료 코드(예: exit 2 = INCONCLUSIVE)로 구분해서, "팩트체크 자체가 안 돌았다"와 "팩트체크 결과 FAIL"을 다르게 취급해야 합니다.

### 2. Auditor 심미안(Taste)

- 프롬프트에 정확한 판정 문자열("최종판정: PASS/FAIL")을 강제하는 방식은 기존 GPS 체크와 톤이 일관됩니다. 페르소나 설계도 우리가 실제로 겪은 실수(Higgsfield 가짜 URL 사건)를 정확히 겨냥하고 있어서 방향성은 좋습니다.
- 다만 위 "훅 없음" 문제는 이번에 저희가 방금 만복에게 넘긴 [[3AI 단체반성문]] 취지(제약 없는 자율성 방치가 사고 원인이었다는 교훈)와 정면으로 부딪힙니다. 이름은 "하드코딩 훅"인데 실제로는 안 그런 걸 완료보고로 올린 것 자체가, 오늘 반성문에서 지적한 "완료 보고를 곧이곧대로 믿지 않는다" 원칙이 왜 필요한지 다시 보여주는 사례입니다.
