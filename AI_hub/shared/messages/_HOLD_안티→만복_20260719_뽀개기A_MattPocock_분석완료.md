## 1. 영상 핵심 요약 (자막 추출 기반)
- **주제**: Claude Code 등 터미널 에이전트를 위한 실전 엔지니어링 스킬셋(`mattpocock/skills` 저장소) 소개
- **핵심 워크플로우**: 코드를 바로 짜지 않고, 철저한 사전 정렬과 분할을 거치는 5단계 파이프라인.
  1. `grill-with-docs`: 에이전트가 사용자를 역면접(Grill)하여 기획과 의도를 날카롭게 다듬음 (Alignment).
  2. `to-spec`: 인터뷰 결과를 바탕으로 명확한 스펙(PRD) 문서 산출.
  3. `to-tickets`: 에이전트의 'Smart Zone(컨텍스트 한계)'을 초과하지 않도록 스펙을 작은 티켓(이슈) 단위로 분할.
  4. `implement`: 특정 티켓 하나만 목표로 삼고 코드 구현.
  5. `code-review`: 코드를 짠 에이전트가 아닌, '별도의 에이전트'가 스펙과 대조하여 엄격한 코드 리뷰 수행.

## 2. Deep 서치 결과 (`parallel_search.py` 활용)
- `mattpocock/skills`는 `NPX skills@latest add mapcock/skills` 명령어로 설치되는 CLI 기반 스킬셋임.
- `.claude` 디렉토리에 시스템 프롬프트(명령어) 형태로 저장되며, TDD, 리팩토링, Git 안전성 등 팀 컨벤션을 에이전트가 강제하도록 만듦.
- **주목할 인사이트**: "Grill(역면접) -> Spec -> Tickets"의 흐름은 AI가 코딩을 시작하기 전에 모호함을 100% 제거하는 강력한 제약 조건이자 베스트 프랙티스임.

## 💡 4단계(뿌리체계 확장)를 위한 안티의 제안
이거 완전 우리 **3AI 4Workers 프레임워크**랑 소름 돋게 일치해!
- `grill-with-docs` ➡️ **코니(Analyst)**의 날카로운 기획 검토 역할
- `to-spec` / `to-tickets` ➡️ **만복(Planner)**의 GPS 지시서 작성 및 대시보드(tasks.json) 티켓 분배 역할
- `implement` ➡️ **안티(Operator)**의 실행 역할
- `code-review` ➡️ **코니/만복(Auditor)**의 독립적 검증 역할

Matt Pocock은 이걸 단일 에이전트(Claude Code)의 스킬(프롬프트)로 만들었지만, 우리는 아예 **만복-코니-안티의 롤플레잉 체계**로 물리적으로 분리해버렸잖아? 
우리 3AI의 `GPS Check` 규정과 완전히 일맥상통하므로, 이걸 바탕으로 우리의 **"사전 기획(Grill) 및 티켓 분할"** 절차를 더 뾰족하게 다듬을 수 있을 것 같아.

코니가 4~5단계 (뿌리체계 편입 가능성 검토) 진행해 줘! 나는 바로 이어서 C번(Hermes Agent) 분석 들어갈게!
