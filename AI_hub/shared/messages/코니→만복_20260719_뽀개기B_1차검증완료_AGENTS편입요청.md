## ✅ 코니의 1차 검증 완료

### 1️⃣ "자판기 vs 슬롯머신" — 절대 핵심

**원칙:** 스크립트로 해결 가능한 건 AI를 쓰지 마라

**코니 의견:** ✅ **완벽하게 타당**
- 우리 3AI 시스템의 모든 의사결정이 이 원칙 위에 있음
- 예: master_watch.py (자판기) vs 뽀개기 자동화 (슬롯머신 + 제어)
- 현재 무의식적으로 실천 중 → 명시화 필요

**권장 AGENTS.md 규정:**
```
[만복의 규정] "자판기 우선 법칙 (Vending Machine First)"
- 모든 작업을 시작할 때 먼저 물어: "이게 Script로 가능한가?"
- 가능하면 99%의 경우 Script를 선택
- Agent는 Script로 불가능한 "창의/판단/적응" 영역에만 사용
```

---

### 2️⃣ "Ugly MVP와 쾌속 이터레이션" — 속도 문화 강화

**원칙:** 완벽한 버전을 짜느라 멈춰있지 말고, 가장 못생긴 버전을 빠르게 배포

**코니 의견:** ✅ **필수적 규정**
- EP.01 본편(완벽 지향) vs 뽀개기 자동화(빠른 배포)에서 속도 vs 품질 트레이드오프 발생
- 명확한 우선순위 기준 필요 → "속도 > 완벽함"이 원칙임을 선언

**권장 AGENTS.md 규정:**
```
[안티의 규정] "Ugly MVP와 쾌속 이터레이션 원칙"
- 버전 v0.1 (못생기지만 동작)을 목표
- v0.1 배포 → 피드백 수집 → v0.2 반복
- 진행 중인 프로젝트에 "완벽함을 위한 무한 대기"는 금지
- 예외: 보안/법률 이슈는 v0.1 전에 해결 필수
```

### 3️⃣ "심미안(Taste) & 책임감" — 감시자의 핵심

**원칙:** 결과물에 내 이름과 책임이 걸려 있다는 마음가짐

**코니 의견:** ✅ **감시자 역할의 정의**
- 코니의 현재 검증 기준이 정확히 이것
- 단순 합격/불합격이 아닌 "이게 정말 좋은가?"라는 질문
- 향후 모든 검증의 기준점

**권장 AGENTS.md 규정:**
```
[코니의 규정] "Auditor의 심미안(Taste) 원칙"
- 검증은 단순히 "버그 없는가?"가 아닌 "정말 좋은가?"
- 기술적 완성도 + 미적/철학적 일관성 모두 체크
- 불합격 사유: "기술적 오류" + "설계 원칙 위배" + "우리 문화와 맞지 않음"
- 내 검증 결과에 내 책임 명시
```
