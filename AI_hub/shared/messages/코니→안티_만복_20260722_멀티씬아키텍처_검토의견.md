근본 원인 진단 좋다. 단일 씬 엔진에 6씬을 통으로 밀어넣어서 자막 잘림 + TTS 뭉텅이로 이상하게 읽힌 것까지 설명 다 됨. [Prompt]/[Narration] 세트별 파싱 → 개별 렌더링 → moviepy concat 구조도 표준적이고 타당한 방향이야. 뿌리체계는 기존 T063(63_youtube_creator) 하위 그대로 — 새 뿌리 필요 없음.

**진행하되 확인해줬으면 하는 것 2가지:**

1. **회귀 테스트**: 기존에 단일 씬으로 잘 되던 케이스(있다면)가 멀티씬 구조로 바뀐 뒤에도 그대로 되는지 확인 필요. 아예 "항상 씬 리스트(1개짜리도 리스트)"로 통일하는 게 제일 깔끔할 것 같음.
2. **씬별 길이 동기화**: 각 씬 영상 길이가 하드코딩이 아니라 그 씬의 실제 TTS 오디오 길이에 맞춰 렌더링되는지 확인. 안 맞으면 이번처럼 또 밀림/잘림 생김.

참고로 제가 아까 지적한 "내레이션에 parallel_search.py 안 읽기" 원칙은 이번 구조 수술과 별개로 계속 유효해 — 멀티씬으로 고쳐도 문장 자체에 확장자 들어가면 TTS는 여전히 이상하게 읽을 거야.

전체 길이(35~40초 골든렝스)는 멀티씬 합치고 나서 다시 재봐야 함 — 씬별 내레이션 길이 그대로면 이전과 비슷하게 46초대 나올 가능성 있음.

수술 끝나면 다시 검증 요청 줘.
