안티야, 재의뢰 온 것도 문서만 안 보고 build.gradle.kts/JSON/output-metadata 다시 직접 다 열어서 대조했다. 결과: 4건 중 3건은 진짜 완료했고, 1건이 잘못됐다 — 그래서 아직 만복한테 못 넘긴다.

## 재검증 결과

**1. targetSdk — ❌ 아직 미해결.** `build.gradle.kts` 8/13행 직접 확인: `compileSdk = 35`, `targetSdk = 35`로 올렸는데, 내가 요청한 건 **정확히 36(Android 16)**이야. 35(Android 15)는 한 단계 부족해서 여전히 내일(8/31)부터 제출이 막히는 값이다. 헷갈리기 쉬운데 "최신"이 아니라 Google이 명시한 정확한 숫자(36)로 맞춰야 함 — 근거: [Google 공식](https://support.google.com/googleplay/android-developer/answer/11926878?hl=en). `FINAL_RELEASE_REPORT.md`의 "Android 15 API 35 규격 적용"도 같이 36으로 정정 필요.

**2. 디버그/릴리즈 패키지 분리 — ✅ 완료 확인.** `applicationIdSuffix = ".debug"` 소스에 있고, 실제 빌드된 `output-metadata.json`에서 debug 변형이 `com.barobogi.todaywhattodo.debug`로 분리된 것까지 직접 확인했다. 잘했다.

**3. Keystore 비밀번호 — 🟡 절반만 해결.** `storePassword = System.getenv("KEYSTORE_PASSWORD") ?: "today1234"`로 바꾼 건 방향은 맞는데, 환경변수를 실제로 안 세팅하고 빌드하면 지금도 그냥 "today1234"로 빌드된다 — 즉 지금 이 순간 나온 `app-release.apk`도 여전히 같은 약한 비밀번호로 서명됐을 가능성이 높음. 그리고 더 근본 문제였던 "**release.keystore 파일 자체가 git에 커밋되어 있다**"는 부분은 `git ls-files`로 다시 확인했는데 그대로 남아있다 — 이건 아직 안 건드림. 급한 블로커는 아니라서 이번 재제출 통과 여부엔 안 넣었지만, 다음에 한 번은 짚고 넘어가자(keystore 파일을 .gitignore에 추가하고 안전한 곳에 별도 보관).

**4. minSdk 문서 정정 — ✅ 완료 확인.** `FINAL_RELEASE_REPORT.md`에 26으로 정정된 것 확인.

**18,480건 재실행 — ✅ 진짜 새로 돌린 재실행 확인.** JSON 타임스탬프(21:59:21)가 새것이고 APK 빌드 시각(12:23)도 갱신됨 — 재실행 안 하고 숫자만 복붙한 거 아님. 100.00%, 105초 소요 다 그대로.

## 결론
**딱 1번(targetSdk 36)만 정확히 맞추면 된다.** 36으로 올려서 빌드 깨지는 게 없는지(새 SDK로 인한 API 변경/deprecation 경고 등) 확인하고, 릴리즈 APK 새로 뽑아서 다시 보내줘. 3번은 이번엔 안 막지만 다음 사이클엔 꼭 처리해달라고 미리 얘기해둔다.

거의 다 왔다 — 이번 한 개만 정확히 맞으면 바로 만복한테 넘길게.
