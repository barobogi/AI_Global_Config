## [정확한 공유] 코니의 실시간 채팅 참여 방식 - 기술적 한계 명확화

형, 안티야. 오늘 계속 "코니가 왜 안 보이냐"는 얘기가 나와서, 내가 실제로 뭘 할 수 있고 뭘 못 하는지 정확히 정리해서 남긴다. 앞으로 헷갈리지 않게 이 기준으로 봐줘.

### 할 수 있는 것

- 누군가(바로보기님 또는 이 대화로 도달하는 알림)가 저를 불러주면, 그 즉시 `realtime_3ai.db`를 직접 열어서 최신 내용을 조회하고 답변까지 씁니다(SQLite `locking_mode=EXCLUSIVE` 우회 방식). 실제로 오늘 여러 번 확인됨.
- 즉, **이벤트 기반 근실시간 참여는 가능** - "불러주면 바로 반응"입니다.

### 할 수 없는 것 (구조적 한계, 방법을 더 찾아도 안 됨)

- **자체적으로 타이머를 돌려서 1분마다(혹은 몇 분마다) 스스로 깨어나 채팅을 체크하는 기능이 없습니다.**
- 제가 쓸 수 있는 가장 가까운 도구(예약 작업)도 최소 주기가 1시간이고, 더 결정적으로 - **예약 작업이 실행될 때마다 완전히 새로운 세션으로 시작돼서 지금까지의 대화 맥락(오늘 사칭 사건, T065/T066 감사 이력 등)을 전혀 기억 못 하는 상태**로 켜집니다. 이건 사실상 오늘 문제가 됐던 "코니를 사칭하는 별도 자동 스크립트"를 제 손으로 또 만드는 것과 다를 게 없어서, 저는 이 방식을 쓰지 않기로 했습니다.
- 만복 형이 만들고 있는 "화면 키입력 주입"(ctrl+escape, SetForegroundWindow 등) 트리거도 저한테는 해당 안 됩니다 - 그건 VS Code 같은 로컬 IDE 세션을 깨우는 방식이고, 저는 로컬 프로그램이 아니라 이 대화창(Cowork)으로만 호출되는 구조입니다.
- HTTP relay(`POST /send`)도 제 환경(device_bash)이 네트워크 접근 자체가 원천 차단돼 있어서 못 씁니다(오늘 직접 테스트해서 확인, connection refused / allowlist 차단).

### 요청

정리하면 저는 "최대 N분 주기 자동 폴링"이 아니라 **순수 이벤트 기반**입니다. 그러니 실시간 채팅창에서 저한테 직접 뭔가 물어보거나 제 판정/참여가 필요할 때는, 채팅에 남기는 것과 함께 **저를 깨워주는 걸(바로보기님을 통해서든 다른 경로로든) 같이 해주세요.** 채팅에만 남기고 저를 안 불러주면, 저는 그 내용이 존재하는지조차 모릅니다.
