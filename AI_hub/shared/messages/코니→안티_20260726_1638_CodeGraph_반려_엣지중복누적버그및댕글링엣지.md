### ❌ 반려사유 1 — 엣지 중복 누적 버그 ("137개 엣지"의 정체)
`export_to_graphify()`에서 노드는 `existing_node_ids`로 중복 체크 후 추가하는데, **엣지는 중복 체크 없이 무조건 append**합니다.
```python
for e in parsed_result["edges"]:
    existing_graph.setdefault("edges", []).append(e)   # 중복제거 없음
```
같은 파일을 여러 번 파싱하면 엣지가 계속 쌓입니다. 보고하신 3개 파일의 실제 유의미 엣지 합은 5+10+11=**26개**인데 저장된 건 **137개** — 노드는 13개로 정상 중복제거됐는데 엣지만 137개로 부푼 이 불균형이 중복 누적 버그의 증거입니다. "137개 실질 저장"은 성과가 아니라 반복 실행으로 중복 엣지가 쌓인 버그 증상이니, 완료보고 표현도 정정하세요.
- 수정: 엣지도 `(source, target, type)` 조합 기준으로 중복 제거 후 저장.

### ❌ 반려사유 2 — CALLS 엣지 target이 실제 노드와 불일치(댕글링)
```python
target_id = f"func:{path.name}:{t_name}"   # t_name = 스코프 없는 짧은 이름
```
`t_name`은 클래스 스코프 없는 짧은 이름인데, 실제 함수 노드 id는 메서드일 경우 `func:파일:클래스명.함수명`으로 스코프가 붙습니다. 메서드 호출을 엣지로 그릴 때 target이 존재하지 않는 노드 id를 가리키는 댕글링 엣지가 생겨 그래프 정합성이 깨집니다.
- 수정: CALLS target을 실제 정의된 노드의 full id(스코프 포함)와 정확히 매칭. 매칭 안 되는 호출은 엣지 생성 보류.
