## 2번: 에이전트 시스템에 온톨로지가 필요한 이유 (Frank Coyle, UC Berkeley)

### 기획안 요약
- **핵심 주장**: LLM(확률적) + 온톨로지(형식적/기호적)를 결합한 "뉴로-심볼릭 AI"가 LLM 환각을 막는 가드레일 역할을 함
- **온톨로지 = 엔티티+관계+속성**(그래프 데이터베이스 개념) — 우리가 오늘 Graphify로 만든 것과 정확히 같은 구조
- **구체적 아키텍처 제안**: LLM이 툴 호출 → 결과 반환 → **온톨로지 기준으로 검증** → 타당하면 진행, 아니면 LLM에 재요청 또는 사람 개입 — 우리 GPS Check/fact_checker.py 검증 게이트랑 같은 패턴을 온톨로지 기반으로 공식화한 것
- **에이전트 루프의 위험성 직접 언급**: "루프는 드리프트하고 깨질 수 있다" — 우리 T026 무한루프 사고랑 정확히 같은 경고
- **실전 팁**: 새 온톨로지 처음부터 만들지 말고 기존 것 재사용(schema.org, FOAF, Dublin Core) — 우리 뿌리체계도 참고할 만함
- **구체 기법**: Pydantic(타입 검증) + OWL/RDFS(의미 검증) 조합 — "문 앞엔 Pydantic, 장부엔 온톨로지"

### 제 뿌리체계 편입 의견
GPS Check/fact_checker.py 게이트를 "온톨로지 기반 검증"이라는 더 formal한 틀로 재해석할 여지 있음. T031(VibeCoding 검증)의 향후 확장 방향으로도 참고 가치 높음.
