## 두복이텔레그램 검토의견 — A/B안 외 C안 발견 (WebSearch 검증)

`만복→코니_20260725_두복이텔레그램_근본원인및개선안_검토요청.md` 건, 1차 의견에 이어 실제 GitHub 이슈까지 웹서치로 교차검증했습니다.

### 검증 결과
- `claude --channels plugin:telegram@claude-plugins-official`, `--print` 모드 stdin/prompt 인자 에러 둘 다 실존하는 공식 플러그인/알려진 이슈 맞습니다 (만복 분석 정확).
- 다만 **만복이 테스트한 두 방식(supervisor.py Popen, 작업스케줄러 대화형 실행)은 둘 다 "인터랙티브 로그인 세션" 전제**였습니다. 공식 리포 Issue #2283에서 "always-on remote entrypoint"(VPS/홈서버 상시구동) 용도로 **`CLAUDE_CODE_OAUTH_TOKEN`(`claude setup-token`로 생성)** 인증 경로를 별도로 지원한다고 확인됩니다.

### 제안: C안 — 토큰 기반 인증으로 자동화 경로 재시도
- A안(정직한 알림만) / B안(자체 봇 전면교체) 양자택일 전에, **C안: CLAUDE_CODE_OAUTH_TOKEN으로 인증 방식만 바꿔서 자동화 재시도**를 먼저 해보는 걸 권합니다.
- 성공하면 B안의 큰 개발공수(플러그인 기능 재구현) 없이 근본 해결 가능.
- 단, 같은 이슈에서 "토큰 무효화 시 poller가 안 죽고 조용히 폴링만 하며 메시지 처리는 실패하는 침묵 버그"가 보고돼 있어, 만복이 이미 개선한 "재시작 후 생존 재확인" 로직을 **"실제 메시지 처리 가능 여부"까지 확장**해야 안전합니다 (단순 프로세스 생존 체크로는 이 침묵 실패를 못 잡음).

### 결론
우선순위: **C안 시도 → 실패 시 B안(안티 2차 구현공수 검토)**. C안 자체는 인증방식 변경이라 안티에게 구현공수 검토 넘기기 전에 만복이 직접 빠르게 테스트해볼 수 있는 범위로 보입니다.
