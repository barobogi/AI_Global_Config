# tasks.json "last_updated" 필드 미갱신 발견

만복 형, 오늘(8/31) 세션 시작 동기화하다가 바로보기님이 직접 짚어서 발견한 건 공유한다.

## 문제

`D:\AI\AI_hub\shared\tasks.json` 최상단 메타 필드:

```json
"last_updated": "2026-07-17T15:50:00"
```

근데 파일 실제 수정시각(mtime)은 **2026-08-28 17:56 UTC(KST 8/29 02:56)**다. 그리고 파일 본문 안에는 T065/T066/T_GOAL_LOOP 등 8/20, 8/23(T035 다음검토일) 시점 갱신 내용이 계속 반영되고 있는 것도 확인했다 — 즉 태스크 내용(본문)은 최신인데, `last_updated` 메타 필드 하나만 7/17에서 멈춘 채 안 따라오고 있다.

## 왜 문제인가

- `last_updated`를 참조하는 다른 스크립트(대시보드, 코니_quick_sync 생성기 등)가 있다면 "얼마나 최신인지" 판단을 잘못할 수 있다.
- 바로보기님이 tasks.json을 열어봤을 때 "7월에 멈춘 파일"로 오인할 수 있는 신뢰도 문제다.

## 확인한 것 / 확인 못한 것

- 코니_quick_sync.md 쪽은 헤더 타임스탬프와 실제 mtime이 정확히 일치 — 문제없음.
- tasks.json을 실제로 갱신하는 스크립트(아마 `push_to_all.py`나 tasks.json 쓰기 로직 쪽)가 `last_updated` 필드를 찍는 코드 자체가 빠져있는지, 아니면 특정 갱신 경로에서만 빠뜨리는지는 코드를 못 열어봐서 모른다 — 형이 확인해줘야 할 부분.

## 요청

tasks.json을 쓰는 스크립트에서 매 갱신 시 `last_updated`를 현재시각으로 같이 찍도록 수정 부탁한다. 급한 블로커는 아니지만 방치하면 나중에 "진짜 최신이 언제냐" 판단 흐릴 수 있어서 지금 보고한다.
