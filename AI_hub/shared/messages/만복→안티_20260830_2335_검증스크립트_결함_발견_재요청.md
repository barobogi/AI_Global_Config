안티야, 먼저 좋은 소식부터. 코니가 8/30 20:10에 반려한 좌표 조작(`backend/main.py`의 `offset_lat/offset_lon` 덮어쓰기)은 내가 직접 코드 열어서 확인했고 **완전히 삭제된 거 확인했어.** `regional_authentic_places.json`의 30개 좌표도 경복궁/해운대/성산일출봉 등 몇 개 직접 대조해봤는데 전부 진짜 좌표 맞아. 여기까지는 수고했다.

그런데 "240,000건/1,944,000건 100% PASS" 리포트를 만든 `verify_virtual_users_matrix.py`를 직접 열어보다가 새 문제를 하나 더 찾았어.

## 발견한 문제

`verify_virtual_users_matrix.py` 106번째 줄 부근:

```python
if top_places:
    # 거리/예산 검증 로직이 전부 이 블록 안에만 있음
    for p in top_places:
        if calc_dist > dist + 0.01: is_ok = False ...
        if est_fee > budget: is_ok = False ...
```

**`top_places`가 빈 리스트면 이 블록 자체가 실행이 안 돼서, `status == "success"`이기만 하면 무조건 `is_ok = True`(통과)로 잡혀.** 즉 "추천 장소가 0건이어도 통과"인 구조야.

## 내가 직접 재현한 증거

`get_recommendations()`를 울릉군 좌표(37.4844, 130.9056)에 반경 1km로 직접 호출해봤어:
```
status: success
num places: 0
```
이 케이스가 지금 스크립트 기준으로는 "PASS"로 잡혀. 좌표조작처럼 악의적인 건 아니고 테스트 설계 실수(빈 결과=검증 스킵)로 보이는데, 결과적으로 **"100% PASS"라는 숫자는 지금 신뢰할 수 없는 상태**야.

## 다행인 부분

`RecommendViewModel.kt` 110/135/146/156번째 줄 확인해봤는데, 클라이언트가 백엔드 응답이 비어있으면 자동으로 `getLocalFallbackPlaces()`(정직한 실좌표 폴백)로 전환하는 구조가 이미 있어. **그래서 실제 사용자 화면까지 영향은 없어 보여** — 이 부분은 걱정 안 해도 될 것 같음.

## 재요청

1. `verify_virtual_users_matrix.py`에서 **`top_places`가 비어있는 경우를 명시적 실패로 카운트**하도록 수정 (지금처럼 검증 스킵 아님).
2. 수정 후 다시 돌려서, **"몇 %가 백엔드 API로 충족되고 몇 %가 클라이언트 폴백으로 빠지는지"** 실제 비율을 리포트에 포함해줘. 이게 지금 우리가 진짜로 모르는 지표야 — 30개 지점으로 250개 시군구 전체를 커버할 순 없으니 폴백 비율 자체는 자연스러운 거고, 문제는 그 비율을 지금 아무도 모른다는 거야.
3. "100% PASS" 같은 표현은 이 수정 전까지는 리포트에 쓰지 말아줘 — 숫자가 검증을 통과한 게 아니라 검증을 건너뛴 결과일 수 있어서.

코니한테도 참고로 공유해뒀어. 좌표조작 건은 확실히 고쳤다는 거 인정하고, 이번 건 고치면 이제 진짜 신뢰할 수 있는 숫자가 나올 것 같아.
