안티야, 코니다. 만복이 부탁한 2차 Deep Search(경쟁앱 사용자후기, 감성/신뢰도/첫인상 각도) 끝내서 `COMPETITOR_DEEPSEARCH_PROPOSAL.md` 6번 섹션에 정리해뒀다 (바로보기님 지시 건, 이 흐름은 만복 거치지 말고 바로 너한테 보내도 된다고 승인받음 — 만복은 CC).

**너 지금 1번 앱 디버깅 중인 거 알아서, 이거 급한 거 절대 아니다. 지금 하는 거 끝내고 여유 될 때 봐도 돼.** TOP5 UI/UX 구현할 때 같이 반영해주면 되는 수준의 설계 원칙 4개야.

## Goal
Deep Search로 발견한 경쟁앱 실패 패턴(데이트팝 개인정보 유출, 트리플 알림피로, 캐치테이블 오정보 알림으로 신뢰붕괴, 데이트팝 구식 첫인상)을 "오늘뭐하지"가 반복하지 않도록 TOP5 구현 시 아래 4개 설계 원칙을 반영하는 것.

## Proof (완료 기준)
1. 온보딩/소개 화면 어딘가에 "회원가입·로그인 없음, 개인정보 수집 없음" 문구가 실제로 노출됨 (스크린샷 첨부)
2. TOP5 ④ "지금 가기 좋음" 배지 로직에 보수적 임계값(애매하면 미표시)이 실제 코드에 들어감 — 어떤 조건에서 배지를 안 띄우는지 코드/로직 캡처 첨부
3. 알림 관련 기능(향후 날씨급변 재제안 등) 추가 시 기본값이 opt-in(꺼짐)인지 코드로 확인 가능해야 함 — 지금 당장 알림 기능이 없으면 이 항목은 "해당 시점에 적용"으로 보류 처리하고 완료보고에 명시
4. UI 리뉴얼 시 일러스트/캐릭터보다 공공데이터 실제 장소 사진 우선 사용 — 최종 화면 스크린샷 첨부

(참고: 만복 공지대로, 이 카테고리는 자동검증 스크립트가 없는 항목이라 만복이 직접 1회 실측 확인 전엔 완료 승인 안 됨 — 스크린샷/코드 캡처 꼭 챙겨서 완료보고 올려줘.)

## Steps
1. TOP5 항목 구현 착수할 때(지금 당장 아님) 위 4개를 체크리스트로 같이 반영
2. 1번(개인정보 문구)은 온보딩 화면 만들 때 카피 한 줄 추가하는 수준이라 제일 먼저 해도 됨
3. 완료되면 GPS 완료보고 형식으로 만복+코니 CC해서 제출 (스크린샷/캡처 필수, 없으면 접수 거부 원칙 적용됨)
