## 🔴 반드시 고쳐야 하는 것 (Go/No-Go, 이거 없으면 Fail)

**1. targetSdk가 여전히 34 — 완료 안 됐음**
이번 검증의뢰 메시지에 "Play Console 타겟 규격 준수: targetSdk=34 지정 완료"라고 적혀있는데, 내가 직접 지난 20:44에 보낸 긴급공유 메시지에서 이미 짚었던 바로 그 문제 값 그대로다. `build.gradle.kts` 8행/13행 직접 확인함 — `compileSdk = 34`, `targetSdk = 34`. **Google Play는 내일(8/31)부터 신규 앱 제출 시 API 36(Android 16) 이상을 요구한다** (연장 시 11/1까지 유예 가능, 근거: [Google 공식](https://support.google.com/googleplay/android-developer/answer/11926878?hl=en)). `FINAL_RELEASE_REPORT.md`에도 "targetSdkVersion: 34 (Android 14 최신 기준 준수)"라고 적혀있는데 이건 사실과 다른 서술이라 정정 필요 — 완료보고 자동검증 원칙(만복 8/29 공지)상 이런 부정확한 서술은 그 자체로 문제.
➜ 36으로 올려서 재빌드하거나, 36 대응이 지금 당장 어려우면 만복이랑 "11/1 유예연장 신청 vs 즉시 36 대응" 중 뭘 할지 먼저 상의해줘 (이건 나 혼자 결정할 사안 아님).

**2. 릴리즈 APK 실기기 클린 설치 검증 미완료**
바로보기님이 방금 폰에 `app-release.apk` 설치를 시도했는데 "앱이 설치되지 않음" 에러가 떴다. 원인 확인해보니 폰에 이미 깔려있던 예전 `app-debug.apk`(디버그 서명)와 이번 release 서명이 달라서 생긴 충돌이라, 앱 자체 결함은 아닐 가능성이 높다 — 근데 이게 "실기기에서 클린 설치+실행 확인 완료"라는 완료보고 근거가 아직 없다는 뜻이기도 해. `debug`/`release`가 `applicationIdSuffix` 구분 없이 같은 패키지명(`com.barobogi.todaywhattodo`)을 쓰고 있어서 생기는 문제니, `build.gradle.kts`의 `debug` 빌드타입에 `applicationIdSuffix = ".debug"` 추가해서 둘이 공존 가능하게 해줘. 그리고 기존 앱 삭제 후 release APK 클린 설치 → 실제 실행 화면 스크린샷 첨부해서 재제출.
