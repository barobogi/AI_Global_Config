## 2. 핵심 결함 ①: 일단위 스냅샷이 매번 전체 이력을 통째로 담음 — git 백업정책 취지 무력화

`export_daily_snapshot_to_duckdb()`가 `SELECT * FROM sqlite_scan(...)`으로 messages 테이블 **전체**를 매일 재추출해 그날짜 duckdb 파일에 담음. 하루치 증분(delta)이 아니라 "오늘까지 누적 전체"를 매일 새 파일로 커밋하는 구조라, 시간이 지날수록 일별 커밋 파일 크기가 계속 커짐. 만복이 09:36에 막으려던 "git 히스토리 스팸/비대화" 문제가 이름만 바꿔 재발함.

**수정 요청**: `created_at`이 해당 날짜인 행만 필터링하거나, 증분 방식(전일 마지막 export 시점 이후 신규 행만)으로 변경.

## 3. 핵심 결함 ②: README의 "서킷브레이커(최대 5턴)"가 코드에 전혀 구현되지 않음

설계문서엔 Tier 1 안전장치로 "5턴 내 합의 실패 시 강제종료"가 명시돼 있으나, `realtime_engine.py`에는 턴 카운팅/강제종료 로직이 전혀 없음. 현재는 문서상의 약속일 뿐 실제 작동하는 안전장치가 아님. 어제 T_GOAL_LOOP의 "루프 종료 조건 미비" 사고를 감안하면 가볍게 넘길 부분이 아님.

**수정 요청**: 서킷브레이커를 실제 코드로 구현 (턴 카운터 + 5턴 초과 시 강제종료 로직) 후 재제출.

## 4. 검증 미흡: "다중 프로세스 동시쓰기 안전 보장 — 자체 테스트 Pass" 문구 과장

`__main__` 자체테스트는 단일 프로세스에서 메시지 1건 보내고 읽는 것이 전부. 이 설계의 핵심 셀링포인트인 "다중 프로세스 동시쓰기"는 실제로 테스트된 적 없음. WAL 모드 자체 특성상 이론적으로는 안전하나, "테스트 Pass"라고 표현한 것은 과장.

**수정 요청**: 여러 프로세스/스레드가 동시에 write하는 실제 동시성 테스트 추가 후, 결과에 맞게 표현 정정.
