## Goal
아래 4건(특히 상위 3개는 Go/No-Go 게이트 — 안 고치면 Play Store 제출 자체가 물리적으로 안 됨) 반영해서 다음 검증의뢰 때 같이 올려주면 됨.

## 발견 (직접 실측, 파일/코드 근거)

1. 🔴 **긴급 — 마감 내일(8/31)**: `android/app/build.gradle.kts` 8행/13행에 `compileSdk = 34`, `targetSdk = 34`로 되어있는데, Google Play가 **2026-08-31부터 신규 앱 제출 시 Android 16(API 36) 이상**을 요구함(연장 신청 시 11/1까지 유예 가능). 지금 그대로면 내일부터 제출 자체가 막힘. 출처: [Google 공식 Target API 요건](https://support.google.com/googleplay/android-developer/answer/11926878?hl=en)
2. 🔴 **치명 — 앱 아이콘이 시스템 기본값**: `AndroidManifest.xml` 10행 `android:icon="@android:drawable/sym_def_app_icon"` 그대로고, `res/mipmap-*` 폴더 자체가 없음(res엔 values만 존재). 커스텀 런처 아이콘(adaptive icon 권장) + 512x512 스토어용 고해상도 아이콘 둘 다 필요.
3. 🔴 **치명 — 릴리즈 서명 설정 전무**: 프로젝트 전체(`*.gradle*`, `*.properties`) grep해도 `signingConfigs`/`storeFile`/`keystore` 관련 코드가 하나도 없음. 지금 빌드하면 디버그 서명으로 나갈 텐데, 그건 Play Console에 업로드 자체가 거부됨. release keystore 생성 + `signingConfigs.release` + `buildTypes.release.signingConfig` 연결 필요.
4. 🟡 **경미(권고)**: release 빌드 `isMinifyEnabled = false`(R8/proguard 미적용, 블로커 아님) / `PLAY_STORE_METADATA.md`의 개인정보처리방침 URL이 `raw.githubusercontent.com` md 원본이라 정식 렌더링 웹페이지가 아님(GitHub Pages 등으로 전환 권장).

## Proof (완료 기준)
- targetSdk 36 반영 후 정상 빌드 성공 로그 (또는 만복 판단하에 11/1 유예 연장신청으로 갈지 결정 — 이건 안티 혼자 결정할 사안 아니니 만복한테 확인 받아줘)
- 커스텀 아이콘 적용된 실제 실행 화면/런처 아이콘 스크린샷
- release 서명된 AAB/APK 빌드 로그 (디버그 아님을 확인할 수 있는 근거)
