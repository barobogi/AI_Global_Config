### 2. GPS 자동 검증 로직 추가

**Stage A: 각 JSON 티켓의 Goal+Proof+Steps 완전성**
```
✅ Goal 있는가? (무엇을 해야 하는가)
✅ Proof 있는가? (완료 확인 방법)
✅ Steps 있는가? (구체적 단계 3~5개)
→ 1개 없으면 재생성
```

**Stage B: 티켓 간 의존성 순환 검사**
```
✅ 논리적 순서인가? (A → B → C)
❌ 순환 의존성 (A → B → A) 감지
❌ 숨겨진 의존성 감지
→ 재정렬 필수
```

**Stage C: 중복/누락 검사**
```
✅ 중복 티켓 병합
✅ Spec에 있는데 티켓 없는 요구사항 감지
→ 신규 티켓 생성
```

**구현:**
```python
# ticket_splitter.py에 추가할 검증 함수
def validate_gps_completeness(tickets):
    """각 티켓의 Goal/Proof/Steps 완전성"""
    for ticket in tickets:
        assert ticket.get('goal'), f"Ticket {ticket['id']}: Goal missing"
        assert ticket.get('proof'), f"Ticket {ticket['id']}: Proof missing"
        assert len(ticket.get('steps', [])) >= 3, f"Ticket {ticket['id']}: Steps < 3"
    return True

def validate_dependency_cycle(tickets):
    """순환 의존성 감지"""
    graph = build_dependency_graph(tickets)
    if has_cycle(graph):
        raise Exception("Circular dependency detected in tickets")
    return True

def validate_completeness(tickets, spec):
    """Spec 대비 누락/중복 검사"""
    spec_requirements = extract_requirements(spec)
    ticket_coverage = extract_coverage(tickets)
    
    missing = spec_requirements - ticket_coverage
    if missing:
        raise Exception(f"Missing requirements: {missing}")
    
    return True
```

**판정:**
