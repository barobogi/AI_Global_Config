## Goal
Play Store 등록 전에, 경쟁앱들이 실제로 겪은 사용자 불만 중 우리 앱도 겪을 위험이 있는 걸 미리 막는다.

## Proof (완료 기준)
1. `score_engine.py` 카테고리 다양성 로직 추가 후 `test_hard_filter.py` 등 기존 테스트 전부 통과 + 신규 테스트(다양한 카테고리 3코스 검증) 통과 로그
2. 온보딩 화면(또는 결과 화면 최초 진입 시)에 공공데이터 커버리지 안내 문구 반영된 스크린샷
3. Render 콜드스타트 안내 문구 반영된 스크린샷

## Steps (우선순위순)
1. **[최우선, 코드 리스크]** `backend/recommend/score_engine.py`의 `generate_recommendations()`(156행 근처) — 지금 점수 내림차순 top_k만 그대로 뽑는 구조라 상위권이 한 카테고리(예: 카페)로 쏠리면 3코스가 다 비슷해 보이는 리스크 실재. **카테고리별 최소 1개씩 우선 배정 후 남는 슬롯을 점수순으로 채우는 다양성 로직**으로 수정. (데이트팝 후기 "코스 개수 적어서 아쉬움" 사례에서 도출)
2. **[UX 문구]** 온보딩/최초 진입 화면에 "검증된 공공데이터 기반 추천 — 신상/비제도권 핫플은 등록 안 됐을 수 있음" 안내 추가 (트리플 후기 "앱에 없는 정보는 입력 안 됨" 대응)
3. **[UX 문구]** 결과 로딩 화면에 "첫 요청은 서버 기동으로 최대 1분 걸릴 수 있음" 안내 추가 (Render 무료 인스턴스 콜드스타트 대응, 데이트팝 "버벅임/서버장애" 후기 대응)
4. 아래 2개는 우리 앱 구조상 해당 없음 확인됨 — **조치 불필요**:
   - 리뷰 신뢰도/조작 의혹(캐치테이블 사례) — 우리는 자체 리뷰시스템 없음
   - 환불/취소 분쟁(마이리얼트립·캐치테이블 사례) — 우리는 결제/예약 기능 없음
