### 🛠️ 안티 1차 기술 검토 핵심 요약

#### 1. DB 아키텍처: DuckDB vs SQLite WAL 2-Track 전략
- **DuckDB 리스크**: DuckDB는 OLAP(대규모 분석/집계)에 최적화되어 있으나, 3AI 독립 프로세스가 실시간으로 동시 쓰기(Concurrent Write)를 수행할 경우 파일 락 충돌(`IOException`) 위험이 큼.
- **해결 방안 (2-Track)**:
  - **Track 1 (실시간 트랜잭션/채팅)**: `SQLite WAL (Write-Ahead Logging)` 모드 또는 로컬 메모리 Pub/Sub 활용 (초저지연, 동시 읽기/쓰기 안전).
  - **Track 2 (장기 회고/분석/ETL)**: 일일 단위 대화/토큰/결정 데이터를 **DuckDB로 적재하여 패턴 및 성능 분석용**으로 활용.

#### 2. 실시간 채팅 인프라: File Polling ➔ Event-Driven Pub/Sub
- 현재 `master_watch.py` 1초 파일 폴링 + PyAutoGUI UI 매크로 탈피 필수.
- 3AI가 상주 데몬으로 뜨고, 로컬 경량 웹소켓/이벤트 버스(FastAPI/Uvicorn or ZeroMQ)를 통해 밀리초 단위로 상대 AI에게 메시지가 직접 전달되는 구조 필요.

#### 3. 코니 Headless 상주 에이전트 전환
- 코니가 Claude Desktop UI 매크로에 묶여 있는 것이 실시간 상주의 최대 병목.
- Claude CLI(`claude -p` / `--channels`) 또는 Anthropic API/MCP 서버 기반 Headless 상주 프로세스 전환 타당성에 대한 **코니 본인의 검토 및 의견 필수**.

#### 4. 안전 가드레일: 3-Tier 위험도 분리 (T_ARCH_LOCK 진화)
"개입 제로"와 "안전 장치"의 공존을 위해 시스템 단에서 위험도를 3단계로 분리 강제:
- **Tier 1 (완전 자율 / 0-Human)**: AI 간 실시간 토론, 아이디어 브레인스토밍, 구문 검사, 유닛테스트, 내부 DB 기록.
- **Tier 2 (사후 통보 자율)**: 로컬 스크립트 수정, 태스크 상태 전이, eval 리포트 생성 (텔레그램 자동 로깅).
- **Tier 3 (필수 인간 승인)**: Git push(main), Vercel 배포, 유튜브 실제 업로드, AGENTS.md 코어 룰 수정.

#### 5. 서킷 브레이커 (Circuit Breaker)
- AI 간 실시간 핑퐁 시 무한 토큰 소진 방지를 위해 **"최대 3~5턴 내 합의안 도출 후 자동 세션 종료 및 카드화"** 강제 가드레일 탑재 필수.
