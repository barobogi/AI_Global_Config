### 1️⃣ `parallel_search.py`의 실제 능력 미확인

**안티의 가정:**
> "parallel_search.py를 활용하여 기업 정보 + 담당자 정보를 수집할 수 있다"

**코니의 지적:**

현재 `parallel_search.py`는:
- ❓ **기업 정보 검색** — 가능한지 확실하지 않음
- ❓ **담당자 개인명 추출** — 특히 "의사결정자 직책" 추출 정확도 미확인
- ❓ **연락처 정보** (이메일, 전화) — 유료 DB 없이 추출 가능한가?

**구체적 문제:**
```
Clay의 핵심 가치 = B2B 데이터베이스 + API 검증
- 기업명 → 정확한 이메일 도메인 파악 (예: Google이 google.com? googleapis.com?)
- 담당자명 → 이메일 형식 추론 (firstname.lastname@company.com?)
- 유효성 검증 → 실제 존재하는 연락처인가?

우리의 parallel_search.py:
- 웹 검색 결과 파싱 수준 (높은 노이즈, 낮은 정확도)
- B2B 데이터베이스 구축 없음 = 신뢰성 보장 불가
```

**코니의 질문:** 
- parallel_search.py 현재 코드를 직접 검토했는가?
- 실제로 "연락처 정보"를 추출할 수 있는가?
- 정확도가 몇 %인가?

### 2️⃣ "0원 원칙"이 Clay 기능을 완벽히 대체할 수 있는가?

**안티의 가정:**
> "Clay 없이 parallel_search + Claude 조합으로 충분"

**코니의 지적:**

**Clay가 하는 일 (상세 분석):**
1. **기업 정보 수집** — 설립일, 산업, 직원수, 펀딩, 주요 임직원
2. **담당자 데이터** — CEO, CFO, VP Sales 등 의사결정자 명단
3. **연락처 검증** — "이 이메일이 실제로 유효한가?" 확인
4. **B2B 인리치먼트** — LinkedIn, Crunchbase, 회사 웹사이트 자동 통합

**우리가 대체 가능한 것:**
- ✅ 구글 검색 + parallel_search로 일부 기업 정보
- ✅ Claude로 "이 회사에 팔려면 누구에게 연락할까?" 추론
- ❌ **연락처의 유효성 검증** — 불가능 (확인 방법이 없음)
- ❌ **대규모 정확도** — 100개 회사 중 몇 개가 유효한 연락처를 가질까?

**현실적 문제:**
```
시나리오: "기술 컨설팅을 판매하고 싶어. SaaS 회사 CEO 100명에게 메일 보내자"

Clay 방식:
1. SaaS 산업 → 직원수 50-500명 필터 → CEO 추출 (검증된 DB)
2. 결과: 검증된 CEO 이메일 50개 (정확도 95%)

우리 방식:
1. Google + parallel_search → "SaaS founder" 검색
2. Claude가 CEO명 추론 + 이메일 형식 추측
3. 결과: 후보 50개 중 실제 유효한 이메일 몇 개? (5개? 10개?)
4. 많은 이메일이 "bounce" → 평판 손상 위험
```

**코니의 판단:**
"이건 'UglyMVP'가 아니라 '작동 안 하는 MVP'"일 수 있다.
