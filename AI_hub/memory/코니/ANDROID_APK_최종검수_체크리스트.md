# 코니 — 안드로이드 APK 최종 검수 체크리스트 (상용 앱 개발사 릴리즈 결정권자 관점)

> 작성: 2026-08-29. 안티의 "오늘뭐하지" 1차 검증의뢰가 오기 전 미리 준비. 재사용 가능한 범용 체크리스트 + 이번 앱 사전 스캔 결과 포함.
> 원칙: "코드가 있다/컴파일된다"가 아니라 "실제로 상점에 낼 수 있는 상태인가"를 기준으로 본다. 완료보고 자동검증 원칙(2026-08-29 만복 공지)과 동일 선상 — 로그/스크린샷 실측 없는 "완료"는 인정 안 함.

## 0. 이번 건 사전 스캔에서 이미 발견한 것 (검증의뢰 오기 전 선제 확인, 실측 완료)

| 항목 | 실측 결과 | 심각도 |
|---|---|---|
| **targetSdk / compileSdk** | 34 (`build.gradle.kts` 8, 13행 직접 확인) — Google Play는 **2026-08-31**부터 신규 앱 제출 시 **Android 16(API 36)** 이상 필수 (연장 신청 시 11/1까지). 지금 그대로면 **내일부터 제출 자체가 막힘** | 🔴 긴급 (마감 임박) |
| **앱 아이콘** | `AndroidManifest.xml` 10행: `android:icon="@android:drawable/sym_def_app_icon"` — **안드로이드 시스템 기본 플레이스홀더 아이콘 그대로**, `res/mipmap*` 폴더 자체가 없음(res엔 values만 존재) | 🔴 치명 (스토어 심사 반려 + 첫인상 자체가 안 됨) |
| **릴리즈 서명(signing)** | 프로젝트 전체(`*.gradle*`, `*.properties`)에 `signingConfigs`/`storeFile`/`keystore` 관련 설정 전무 — 릴리즈 빌드가 디버그 서명으로 나갈 가능성 높음 | 🔴 치명 (Play Console 업로드 자체가 안 됨) |
| **release 빌드 난독화** | `isMinifyEnabled = false` (proguard/R8 미적용) | 🟡 권고 (APK 용량·역공학 방지 관점, 블로커는 아님) |
| **개인정보처리방침 URL** | `raw.githubusercontent.com`의 md 원본 링크 — 접근은 되나 정식 렌더링된 웹페이지가 아님 | 🟡 권고 (Play Console이 형식상 통과시킬 수는 있으나 전문성 낮아 보임, GitHub Pages 등으로 전환 권장) |
| **권한 범위** | INTERNET, ACCESS_FINE/COARSE_LOCATION만 — 백그라운드 위치 등 과다요청 없음 | ✅ 양호 |

**➜ 위 4개 🔴 항목(targetSdk, 아이콘, 서명, +마감일)은 검증의뢰가 정식으로 오기 전에 안티한테 먼저 알려주는 게 나을 정도로 급함 — 바로보기님께 별도 확인 요청함.**

## 1. 빌드/제출 자격 (Play Console에 올라가기라도 하는가) — Go/No-Go 게이트

- [ ] targetSdk가 제출 시점 Google Play 최소 요구치 이상인가 (수시 확인 필요 — 정책은 매년 바뀜)
- [ ] release 빌드가 release keystore로 서명되는가 (디버그 서명 아님) — `signingConfigs.release` 존재 + `buildTypes.release.signingConfig` 연결 확인
- [ ] Play App Signing 등록 여부 / 업로드키 vs 앱서명키 구분 이해하고 있는가
- [ ] versionCode/versionName이 실제로 증가/설정되어 있는가 (1.0.0, code=1이 첫 출시에 맞는 값인지)
- [ ] AAB(Android App Bundle)로 빌드하는가, APK인가 — 신규 앱은 Play가 AAB를 사실상 요구
- [ ] applicationId가 최종 확정값인가 (출시 후 변경 불가)

## 2. 브랜딩/스토어 리스팅 자산 (첫인상)

- [ ] 커스텀 앱 아이콘 실존 (`res/mipmap-*/ic_launcher.png` 또는 adaptive icon XML) — **시스템 기본 아이콘이면 무조건 반려**
- [ ] 512x512 고해상도 스토어 아이콘 별도 파일
- [ ] 스크린샷(폰 최소 2장, 권장 4장 이상) 실제 화면 캡처로 준비됐는가 — 목업/디자인 시안이 아니라 실제 앱 화면인지
- [ ] Feature Graphic(1024x500) 준비
- [ ] 짧은 설명(80자)/자세한 설명(4000자) 오탈자, 과장 광고 문구(의료·확정 효과 주장 등) 없는지
- [ ] 앱 이름이 다른 상표/브랜드와 충돌하지 않는지

## 3. 기능 실측 (코드가 아니라 실제 동작)

- [ ] 실기기 또는 에뮬레이터에서 실제 설치 → 실행 → 크래시 없이 최소 1회 전체 플로우(조건입력→결과→상세) 완주
- [ ] 위치 권한 거부 시 앱이 죽지 않고 대체 흐름(수동 위치 입력 등) 제공하는가
- [ ] 네트워크 없음/느림 상황에서 무한로딩·크래시 없이 에러 메시지 노출하는가
- [ ] 백엔드(Render 등 무료 인스턴스) 슬립 후 첫 요청 지연(최대 50초+) 시 로딩 UX가 사용자에게 "먹통"으로 안 보이는지 (8/20 회피체크리스트에서 이미 지적된 항목, 실제 반영됐는지 재확인)
- [ ] 화면 회전/다양한 화면 크기(태블릿 포함)에서 레이아웃 깨짐 없는지
- [ ] 다크모드 지원 시 대비/가독성 확인
- [ ] 뒤로가기 버튼/제스처 네비게이션 정상 동작

## 4. 데이터/개인정보 (Play Console Data Safety 폼과 실제 코드 일치 여부)

- [ ] 백엔드에 실제 로그인/계정/개인정보 저장 코드가 없다는 걸 코드로 재확인(이전에 grep으로 확인함 — 이번 빌드에도 변동 없는지)
- [ ] Data Safety 설문(Play Console 제출 항목)에 "수집하는 데이터: 위치(대략/정밀)" 정도로 정직하게 기재되는지, 실제 수집 범위와 설문 답변이 1:1 일치하는지
- [ ] 개인정보처리방침이 실제 웹페이지로 정상 렌더링되는지 (raw 링크 그대로면 개선 권고)
- [ ] 제3자 SDK(카카오 공유 등 추가 예정) 넣을 경우 그 SDK가 수집하는 데이터도 Data Safety에 추가 반영해야 함을 놓치지 않는지

## 5. 정책 준수 (Google Play 정책 — 반려 사유 1순위)

- [ ] 콘텐츠 등급 설문 정확히 작성 (전체이용가 주장과 실제 콘텐츠 일치)
- [ ] 광고 SDK 없음이 실제 코드와 일치 (앱 설명에서 "광고 없음"을 마케팅 포인트로 쓰는 만큼, 숨겨진 광고 SDK 절대 없어야 함)
- [ ] 공공데이터 출처 표기 의무 준수 (TourAPI/기상청 등 출처 명시)
- [ ] 앱 내 텍스트에 경쟁사 비방/과장("압도적 1위" 등 근거 없는 최상급 표현) 없는지

- [ ] 최근 변경분(TOP5 신규 기능 등) 추가된 만큼 새 테스트 케이스도 같이 늘었는지
