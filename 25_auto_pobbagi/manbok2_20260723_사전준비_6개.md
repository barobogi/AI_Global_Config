## 1. ClinePass — Cline용 오픈웨이트 모델 구독 ($9.99/월)
**URL**: https://youtu.be/q_FQegMRWUQ

**핵심 요약**: Cline(오픈소스 코딩 에이전트)에 11개 큐레이션된 오픈웨이트 모델(GLM 5.2, Kimi K3, Deepseek V4 Pro, Minimax M3, Qwen 3.7 Max 등)을 단일 로그인/단일 구독으로 제공. 계정 6개·키 6개·청구서 6개를 하나로 통합. API 대비 요율 제한 2~5배 완화. 가격 경쟁력: 작년 최고급 폐쇄모델 $15/백만 토큰 → 오픈모델 $1.50/백만 토큰 (10배 저렴). 하네스(컨텍스트 읽기→계획→편집→터미널→체크포인트)가 모델보다 중요하다는 게 핵심 메시지.

**Deep 서치 검증**: "Client Pass"는 STT 오기 — 실제로는 **ClinePass** (cline.bot/cline-pass, docs.cline.bot에 공식 문서 존재). 가격도 확인됨: $9.99/월 (첫 달 한정 $4.99).

**뿌리체계 의견**: 우리도 Claude Code CLI subprocess 방식(API 회피 원칙)을 쓰고 있는데, ClinePass 같은 "오픈모델 구독형" 접근은 우리 "API 회피 우선" 철학과 정확히 같은 방향. 다만 Cline 자체를 도입할 계획은 없으므로 **참고자료 등급**에 가까움 — 하네스 설계 철학(컨텍스트→계획→편집→검증→체크포인트) 부분만 우리 뽀개기/렌더링 파이프라인에 참고 가치 있음.

## 3. Orca — 멀티 에이전트 오케스트레이션 ADE
**URL**: https://youtu.be/hcDz6yGT59M

**핵심 요약**: "IDE가 아니라 ADE(Agent Development Environment)". Claude Code/Codex 등 여러 에이전트를 격리된 git worktree에서 동시 실행. 같은 태스크를 여러 에이전트에게 시켜 결과 비교, 또는 다른 태스크를 병렬 할당해 속도 2배. 데모: 동일 프롬프트(히어로 섹션 리디자인)를 Claude/Codex 각각 워크트리에서 실행→결과 비교→머지. 모바일 페어링, 터미널 분할, GitHub/GitLab 네이티브 연동. 무료 오픈소스, 약 2만2천 스타, 840+ 릴리즈(빠른 업데이트).

**Deep 서치 검증**: 실존 확인 — onorca.dev / github.com/stablyai/orca. "에이전트 시대의 병목은 코딩 속도가 아니라 시도 횟수"라는 메시지가 핵심.

**뿌리체계 의견**: 우리 3AI 구조(만복/코니/안티)와 결이 다르지만 상호보완적 — Orca는 **동일 레벨의 에이전트 여러 개를 병렬 실행**하는 도구이고, 우리는 **역할이 다른 에이전트 3개**를 쓰는 구조. 예를 들어 안티가 막힌 버그 하나를 두 가지 방식(예: Kling 우회 vs Pollinations)으로 동시에 시도해볼 때 Orca 방식의 worktree 병렬 실행이 유용할 수 있음. 다만 로컬 설치+설정 부담 있어 **중기 검토 대상**.

## 4. Graphify — Claude Code 지식그래프+Obsidian 메모리
**URL**: https://youtu.be/GnA9xjYWHBg

**핵심 요약**: 워크스페이스를 그래프화(노드+관계)한 뒤 Obsidian vault로 변환, Claude Code가 이 vault를 참조해 훨씬 깊은 맥락 이해를 갖도록 함. 1단계: `/plugin`으로 Graphify 설치→지식베이스 생성(파일 전체 스캔, 노드/엣지 생성). 2단계: "graphify obsidian 명령"으로 vault 변환(2,186개 노드 예시). 3단계: 초기 노드는 관계만 있고 실제 내용이 빈약 → "모든 노드에 원본 컨텍스트를 재통합해줘"라고 지시(`/loop` 또는 `/goal` 사용)하면 원본 마크다운 전체가 각 노드에 채워짐. 결과: 매우 구체적인 질문에 bash 명령 3번만으로 정확한 답 도출(토큰 사용량 극소, 수백~1000토큰).

**Deep 서치 검증**: 실존 확인, graphify.net 공식 사이트, Claude Code 전용 통합(PreToolUse hook으로 파일탐색 전에 지식그래프부터 참조)까지 있음. 관련 도구로 `lucasrosati/claude-code-memory-setup`(Obsidian+Graphify 조합, 세션당 토큰 최대 71.5배 절감 주장)도 발견.

**뿌리체계 의견**: **오늘 6개 중 우리 "개념카드"(local_store.db concepts) 시스템과 가장 직접 경쟁/보완**. 우리는 이미 개념카드 원칙(2026-07-17, "나중에 뭘 물어볼지부터")이 있는데, Graphify+Obsidian 조합은 이걸 자동화된 그래프 구조로 확장한 버전. D:\AI 전체(9개 프로젝트)를 그래프화해서 만복/코니/안티가 공통 참조하는 방식으로 발전시킬 수 있음 — **Agent Memory(2번)와 함께 "우리 메모리 시스템 업그레이드" 후보로 묶어서 검토 추천**.

## 5. AI로 월 $103,000(8개 수익원) 만드는 법
**URL**: https://youtu.be/CkyPE0vZ7Lc

**핵심 요약**: 직접 매출에 기여하는 AI 활용 8가지만 선별(부수적 효과는 제외):
1. **컨설팅**: 인스타/문자/이메일 등 모든 채널 대화를 중앙 로그로 통합해 AI가 항상 최신 맥락 파악 → 고객 만족도↑ 이탈↓
2. **라이브 워크숍**: AI가 교육과정 설계+발표자료+실시간 댓글 감성분석, 하루 세션으로 $33,000
3. **트레이딩**: 24/7 자동매매 에이전트로 $1,000→$180,000, 잠자는 동안 저점 매수 15회 포착
4. **제휴 수수료**: 에이전트가 제휴 마켓플레이스 스캔해서 매칭, 월 $800~900 (자동, 손 안 댐)
5. **재무팀**: 세무/연금 최적화 에이전트 군단(SIPP 활용), 20년간 $1.2M + 법인세 절감
6. **애드센스**: 리텐션 그래프 분석해서 시청자 몰입 구간에 미드롤 광고 배치 → 광고 수익 최적화
7. **브랜드딜**: 이메일 에이전트가 협상+계약서 검토+수정요청+대금 청구까지 (인간 승인만 최종 서명)
8. **온라인 강좌**: 콘텐츠 합성+이미지/음악 생성+갱신 시즌 이메일 시퀀스 자동화, 첫 강좌 $300,000

**뿌리체계 의견**: 코드 편입 대상이 아니라 **비즈니스 전략 참고자료**. 어제 Snag앱(벤지) 사례와 같은 카테고리. 특히 "6번 애드센스 최적화(리텐션 그래프 분석)"는 우리 유튜브 채널에도 바로 적용 가능한 아이디어 — 조회수 데이터 기반으로 우리 콘텐츠 개선점 도출하는 데 참고할 만함.

## 6. Kun의 AI 에이전트 오케스트레이션 끝판왕 세팅 (인터뷰)
**URL**: https://youtu.be/8ZgpAXe5V5w

**핵심 요약**: 전 Meta/Microsoft/Atlassian 엔지니어 Kun의 실제 워크플로우 인터뷰.
- **First Mate**: `agents.md` 파일 기반 코디네이터 에이전트. 여러 "crew mate" 서브에이전트에게 작업 위임, 사용자는 First Mate 하나에게만 말함(음성 입력 위주). 모호한 결정만 사용자에게 에스컬레이션.
- **Herdr**(원문 "Herder", STT 오기): tmux 대체, 에이전트 개념을 이해하는 터미널 멀티플렉서. 모바일 SSH로 동일 세션 접속 가능.
- **No Mistakes**: AI가 만든 코드 diff를 다른 모델(GPT 5.6)로 적대적 리뷰(adversarial review) → 자동수정 또는 애매하면 에스컬레이션 → 테스트→문서화→PR까지 자동. 최근 3개월 통계: 1,000건 변경 중 63%에서 문제 발견/수정.
- **Axi.md**: MCP보다 효율적인 "에이전트 인체공학적 CLI" 설계 원칙 10가지 (토큰 효율 출력, 최소 기본 스키마 등). GitHub CLI가 GitHub MCP 서버보다 항상 더 빠르고 저렴하다는 벤치마크 제시.
- 모델 쿼터 관리 팁: Sonnet 5는 max 추론에서 비용 급증, Grok 4.5는 "Opus인데 빠른 버전", GPT 5.6 Sol이 리뷰어로 우수.

**Deep 서치 검증**: 전부 실존 확인 — Herdr(herdr.dev, ogulcancelik/herdr), No Mistakes(AddyOsmani 블로그에서 언급됨, 실제 패턴), Axi(axi.md, github.com/kunchenguid/axi — "kunchenguid"라는 계정명이 인터뷰이 "Kun"과 일치, 신뢰도 높음).

**뿌리체계 의견**: **오늘 6개 중 우리 3AI 시스템 아키텍처와 가장 깊이 닿아있음.**
- "First Mate + crew mate" 구조 = 우리의 "만복(PM) + 안티/코니" 구조와 본질적으로 동일한 패턴. 다만 Kun은 **음성 입력 우선**, **모호한 결정만 에스컬레이션**하는 규율이 확실함 — 우리도 "만복에게 언제 물어봐야 하는지" 기준을 더 명확히 할 여지 있음.
- **No Mistakes(적대적 리뷰)**: 우리 GPS Check/코니 검증 프로세스에 "다른 모델로 자동 적대적 리뷰"를 추가하면 코니의 수작업 검증 부담을 줄일 수 있음 — **구현 검토 우선순위 매우 높음**.
- **Axi 원칙**: 우리가 만든 MCP 서버들(텔레그램 등)이나 CLI 스크립트를 토큰효율적으로 재설계하는 데 참고할 구체적 기준 10가지 제공.
