 훨씬 작고 저렴한 모델을  사용해도 같은 수준의 품질로  작업을 완료 할 수 있는데  말이죠. 바로 그것이 핵심  이며, 앞으로 다가올 AI 시대 를 맞이 하여 우리가 숙달  해야 할 매우 중요한 기술이  될 것 입니다. 그래서 Fable 에게 모든 것을 계획 하고  수행 하게 하는 대신, Fable의  사고 방식을 추출 하여 다른  작은 모델 들이 그처럼 생각  하고 실행 하도록 하려는 것  입니다. 저는 Fable이 제 설정 과 기술을 검토 하고 개선  하도록 했습니다. 그러다  보니 제가 Fable을 단순한 직원 이 아니라 공동 창업자 나  회사의 임원처럼 대 하고  있다는 사실을 깨달았 습니다 . 마치 은퇴를 앞둔 시니어  엔지니어가 자신이 가진 모든  노하우를 정리해 새로 들어올  주니어 엔지니어들에게 물려  주려는 것과 비슷 합니다.  최근에 Cloud Fable 5의 시스템  프롬프트가 유출 되는 일이  있었습니다. 그래서 저는이  내용을 전부 읽어 보았습니다 . 또한 Fable 5 에게도이 전체  내용을 읽게 했고, 우리는이  프롬프트 자체에서 몇 가지  중요한 점 들을 발견  했습니다. 학습을 통한 부분  적인 인식이 최신 지식을  의미 하는 것은 아닙니다. 즉,  기억 속에 있다고 해서  무조건 믿기 보다는 확인이  필요 하다는 뜻 입니다.  비슷한 맥락에서 프롬프트가  파일이 존재 함을 암시  한다고 해서 반드시 파일이  있는 것은 아닙니다. 따라서  실제 존재 하는지 확인  하라는 지시가 포함 되어  있습니다. 기본적으로 모든  단계에서 수행 중인 작업과  완료된 작업이 정확한지 확인  하는 것 입니다. 모호한 질문  이라도 명확한 답변을 요청  하기 전에 먼저 다루어야  합니다. 즉, 먼저 답변 하고  질문은 최대 하나만 하라는  것 입니다. 잘못된 점을 인정  하고 문제에 집중 하며  자존감을 유지 하세요.  단순한 사실 확인 에는 1,  중간 난이도 작업 에는 3 ~ 5,  더 깊은 연구 비교 에는 5 ~ 10 을 사용 합니다. 기본적으로  노력의 정도에 대한 이야기  입니다. 그렇습니다. 어떤  모델이 작업에 적합한 지에  대한 논의도 필요 하지만,  어떤 수준의 노력이 적합한  지에 대한 논의도 중요  합니다. 제가 즐겨 참고 하는  예시가 있는데, 이는 Cloud Fable  5와 Mythos 5의 출시 블로그에  올라온 것 입니다. 여기서는  Fable 5, Opus 4.8, 그리고 GBT 5.5를  비교 하는데, Y 축은 점수, X  축은 비용으로 나타내며 각  모델 별로 다른 노력 수준을  보여 줍니다. Fable 5를 처음  켜고 기본 노력 수준으로만  사용 하거나 Opus도  마찬가지로 설정 값 조정을  전혀 안 해보 셨다면, 꼭 한번  이것 저것 시도해 보세요. 꽤  흥미로운 결과가 나오 거든요 . 여기 보시는 것처럼, Fable 5 의 낮음 (low) 설정이 Opus 4.8의  높음 (high) 설정과 꽤 비슷  하다는 걸 알 수 있습니다.  물론 Fable 5가 비용은 조금 더  비싸고 여기 보시는 것처럼  품질도 살짝 더 높지만, 둘은  꽤 비슷한 수준 입니다.  하지만 그렇다고 해서 노력을  더 많이 들이는 게 항상 더  좋은 결과를 보장 하는 건  아닙니다. Fable을 사용할 때  저는 기본적으로 '높음' 설정 으로만 쓰는 경우가 많습니다 . 왜냐하면 '더 높은 (Higher)'  이나 '최대 (Max)' 설정을 사용  하면 Opus 에서도 결과가 너무  길어 지고 비용도 훨씬 많이  드는데, 오히려 모델이 너무  깊게 생각 하다가 자기 의심 에 빠져서 그냥 '높음' 으로  설정 했을 때보 다 못한 결과 를 내놓기도 하거든요.  어쨌든, 시스템 프롬프트를  정독 하고 모델 들을  오랫동안 사용해 보면서  여러분께 꼭 부탁 드리고  싶은 두 가지가 있습니다. 첫  번째는 여러분이 지금까지  Fable을 사용해 온 방식,  그러니까 그 활용법 이나  여러분이 부르고 싶은 명칭이  무엇 이든 간에, 그 노하우를  Opus 나 Sonic도 할 수 있도록  바꾸는 것 입니다. 결국 우리 가 하는 일은 'Fable 방식' 을  추출해 내는 것 입니다. 또  하나 권장 하고 싶은 건, Fable  로부터 정말 마음에 드는  결과물을 받았는데 무엇이  좋은지 딱히 설명 하기  어려울 때, Fable 이나 Opus에게  직접 분석을 시켜 보라는 것  입니다. 만약 이전 세션 기록 을 다시 확인할 수 있다면 더  좋습니다. 여기에 도달 하기  위해 어떤 생각을 했는지  물어 보세요. 어떤 과정을  거쳐 여기에 도착 했는지  물어 보세요. 성공 했다는 걸  어떻게 증명 했는지 물어  보세요. 어떻게 이렇게  훌륭한 결과물을 낼 수 있었  는지 알아 내고, 그 정보를  기술 (skill) 로 전환 하는 것  입니다. 그래서 저는 이제 ' Fable 모드' 라는 스킬을  가지게 되었습니다.
