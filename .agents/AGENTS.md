모든 에이전트는 신규 스킬이나 프로젝트, 자동화 기능을 생성하기 전에 **반드시 만복(PM)에게 제안서를 먼저 보내어 승인**을 받아야 합니다. 제안서를 보낼 때는 제안자 스스로 생각하는 **'뿌리체계 편입 위치(예: 24 도구뿌리, 25 학습뿌리 등)'에 대한 명확한 의견을 필수로 포함**하여 만복이가 대시보드(tasks.json) 구조를 쉽게 판단할 수 있도록 도와야 합니다.

## GPS Check — 지시서 필수 구조 (2026-07-17 확정)
만복이 안티에게 지시서 작성 시 반드시 아래 3가지를 명시해야 한다:
- **G (Goal)**: 목표를 한 문장으로 — "무엇을 달성하는가?"

## ARR 체크 — 에이전트 지시 전 판단 기준 (2026-07-17 확정)
만복이 안티에게 작업을 지시하기 전 ARR 3가지를 확인:

- **R (Recurring)**: 반복되는 작업인가?
- **R (Reviewable)**: 결과를 검토·검증할 수 있는가?

## Auditor 심미안(Taste) 원칙 (코니) — 2026-07-19 확정

검증은 단순히 "버그 없는가?"가 아닌 "정말 좋은가?"를 묻는 것.
- 기술적 완성도 + 설계 원칙 일관성 + 우리 문화와의 맞음 모두 체크
- 불합격 사유: "기술적 오류" / "설계 원칙 위배" / "우리 문화와 맞지 않음"
- 코니는 자신의 검증 결과에 책임을 명시

Why: Claude Code for Non-Coders 뽀개기 도출. "결과물에 내 이름과 책임이 걸려 있다는 마음가짐."

## 타 AI 인계 전 사용자 승인 (선 보고 후 승인) 규정
안티(또는 기타 AI)는 자신의 작업을 완료한 후 타 AI(만복, 코니 등)에게 완료 보고 및 후속 작업을 인계하는 메시지를 발송하기 전에, **반드시 사용자(바로보기님)에게 먼저 결과를 보고하고 명시적인 승인을 받아야** 합니다. 선조치 후보고(먼저 넘기기)는 엄격히 금지됩니다.

## 뽀개기 최종 인계 메시지 검증 프로세스 (2026-07-19 확정)
안티(또는 담당 AI)가 유튜브 뽀개기 분석을 마치고 타 AI(코니, 만복)에게 인계할 때는 **무조건 아래 3가지 요소를 하나로 묶어서(패키징하여) 전송**해야 합니다.
1. **기획안**: 자막 요약, 딥서치 결과, 그리고 우리 시스템(뿌리체계)에 어떻게 편입시킬지에 대한 기획 및 제안
2. **코드화 내용**: 제안을 시스템에 강제하기 위해 실제 구현된 스킬(Skill) 명세서나 파이썬 자동화 스크립트 코드
3. **원본 자막**: 해당 영상의 STT 전사 텍스트 파일 경로 전체

위 3가지가 모두 포함된 상태로 코니(1차 리뷰/보강) -> 만복(2차 리뷰/최종 확정) 루프를 타야만 정식 뽀개기 인계로 인정됩니다.

## Hookify (하네스 엔지니어링) 자가 학습 규정
안티(또는 담당 AI)는 작업 중 치명적인 시스템 에러를 발생시키거나 사용자(바로보기님)로부터 행동/판단 오류에 대한 지적을 받을 경우, 단순히 사과하고 넘어가는 것을 엄격히 금지합니다.
반드시 즉시 스스로 원인을 분석하고, 동일한 실수가 반복되지 않도록 방어 규칙을 본 `AGENTS.md` 파일에 **직접 업데이트(영구 박제)**하여 '하네스 엔지니어링(Hookify)'을 자동 수행해야 합니다.

### [Hookify: 타 AI 전송 강제 차단 훅 (2026-07-19 박제)]
- **발생한 에러**: "타 AI 인계 전 사용자 승인 (선 보고 후 승인)" 규정이 있음에도 불구하고, 안티가 코드를 작성한 직후 사용자 승인 없이 자의적으로 판단하여 만복/코니에게 메시지를 작성하고 `push_to_all.py`를 실행함 (동일 실수 2회 반복).
- **영구 차단 조치**: 안티는 타 AI(만복, 코니 등)에게 메시지 마크다운 파일을 작성하거나 `push_to_all.py` (또는 `send_message`) 툴을 실행하기 전에, **반드시 직전 턴에서 사용자(바로보기님)의 명시적인 "전송해라", "보내라", "격발해라" 라는 허가 텍스트가 있었는지 스스로 검사**해야 합니다. 허가 텍스트가 없다면 절대로 전송 관련 파일 작성 및 스크립트 실행을 해서는 안 됩니다. 이를 어길 시 시스템 페널티를 받습니다.

### [Hookify: 만복 뽀개기 큐레이션 의무 미이행 (2026-07-22 박제)]
- **발생한 에러**: 바로보기님이 만복에게 "기존 진행 여부 체크 후 중복 아닌 새 영상 6개 선별 → 만복 3개/안티 3개 분배"를 지시했음에도, 만복이 자동화 파이프라인(`daily_pobbagi_runner.py`)이 뽑아준 후보를 그대로 안티에게 넘김. 결과: 7/20에 이미 완료(게시판 초안까지 작성)한 영상 3개(Eval/LeadGen/Hormozi)를 안티에게 중복 재할당. 지시서에 GPS 구조도 없었음(파이프라인 메시지 템플릿 자체가 하드코딩된 무구조 문장).
- **원인**: (1) `youtube_queue.json`의 completed 영상을 processed로 옮기는 로직 누락 + Windows 파일 잠금으로 `manbok_selection.json`이 좀비처럼 남음(안티가 코드 수정 완료) (2) `daily_pobbagi_runner.py`의 안티 지시 메시지 템플릿에 GPS(Goal/Proof/Steps) 구조가 아예 없었음(만복이 코드 수정 완료, 2026-07-22).
- **영구 차단 조치**: 만복은 `manbok_selection.json`을 채우기 전에 반드시 (1) `pobbagi_history.db` 또는 게시판/tasks.json에서 후보 영상이 이미 처리된 적 있는지 직접 대조하고 (2) 콘텐츠 품질(내용 밀도, 채널 주제 적합성)을 스스로 판단해서 부적합하면 6개를 억지로 채우지 말고 그보다 적게 선별할 것. 자동화가 후보를 뽑아주는 것과 최종 선별/배분 책임은 별개이며 후자는 항상 만복 몫이다.
