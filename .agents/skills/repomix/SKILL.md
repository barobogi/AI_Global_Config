# RepoMix (Repository Packer)

## 🎯 목적 (Goal)
`repomix`는 거대한 코드베이스 전체를 단일 파일(XML, Markdown 등)로 압축 및 구조화하여, 복잡한 프로젝트 파악이나 코드 리팩토링 시 대형 언어 모델(LLM)이 전체 문맥을 한 번에 읽을 수 있도록 도와주는 강력한 분석 스킬입니다.

## 🛠️ 사용 시점 (When to use)
- 새로운 프로젝트나 익숙하지 않은 거대 레포지토리에 처음 진입하여 **전체 구조와 흐름을 파악**해야 할 때
- 여러 파일에 걸쳐 있는 복잡한 버그를 추적하거나 **대규모 리팩토링**을 기획할 때
- LLM(Claude, Gemini 등)에게 특정 모듈의 맥락 전체를 한 번에 전달하고 싶을 때

## ⚙️ 작동 절차 (Steps)
1. **타겟 디렉토리 이동**: 분석할 프로젝트의 루트 폴더(예: `D:\AI\63_youtube_creator`)로 이동합니다.
2. **명령어 실행**: 터미널에서 다음 명령어를 실행하여 레포지토리를 단일 파일로 패킹합니다.
   ```bash
   npx repomix --style xml --output repomix-output.xml
   ```
   (참고: `--style xml`은 LLM이 구조를 파악하기 가장 좋은 형태이며, 필요에 따라 `markdown`으로 변경 가능합니다. 기본적으로 `.gitignore` 규칙을 자동 준수합니다.)
3. **결과물 분석**: 생성된 `repomix-output.xml` 파일의 내용을 `view_file` 또는 `read_file` 툴로 읽어들여, 프로젝트의 폴더 구조, 의존성, 핵심 로직을 분석합니다.
4. **정리 및 삭제**: 분석이 완료되면 너무 거대한 파일이 작업 공간을 차지하지 않도록 `repomix-output.xml` 파일을 삭제합니다.

## 🚨 창작 및 주의 원칙
- **보안 주의**: `repomix`는 `.env` 등의 민감한 파일을 기본적으로 무시하지만, 실행 전 타겟 디렉토리에 API 키 등 보안 정보가 평문으로 노출되어 있지 않은지 주의해야 합니다.
- **토큰 제한 인지**: 패킹된 파일은 매우 거대할 수 있습니다. 100만 토큰을 초과하는 초거대 프로젝트의 경우 LLM의 컨텍스트 윈도우를 초과할 수 있으므로, `--include` 나 `--ignore` 옵션을 사용하여 특정 핵심 폴더만 패킹하는 것을 권장합니다. (예: `npx repomix --include "src/**/*, lib/**/*"`)
