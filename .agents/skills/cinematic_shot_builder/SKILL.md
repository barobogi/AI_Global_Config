# Cinematic Shot Builder Skill

뽀개기 2번(2026-07-22, [호두의 AI 분석실] AI 영상은 이걸로 종결합니다)에서 착안.
참고 오픈소스: `github.com/tsogjavklann/claude-skills/video-prompt-builder` (샷 구조),
Higgsfield 공식 Elements/Soul ID 기능 (캐릭터·장소 일관성, `github.com/Abteeeen/higgsfield-prompting-skill` elements_and_consistency.md 참고).

## 용도 (When to use)
- 코니가 작성한 대본(시놉시스형)이 확정된 직후, 렌더링용 씬별 영상 프롬프트를 만들 때
- EP.xx 본편처럼 캐릭터/장소가 여러 씬에 걸쳐 반복 등장해서 **일관성 유지가 중요한 제작**일 때
- S.00~S.03처럼 짧은 쇼츠라도 카메라 샷(클로즈업/미디엄/와이드)을 자연스럽게 배분하고 싶을 때

## 작동 절차 (Steps)

### 1. 캐릭터/장소 레퍼런스 이미지 확보 (Element 저장)
- 등장인물·장소별로 이미지 1장을 생성/확보 (정면 권장, 여러 씬에 반복 등장하면 정면/측면/클로즈업 3앵글까지)
- 저장 위치: `D:\AI\63_youtube_creator\pipeline\images\elements\{캐릭터명 또는 장소명}.png`
- 이후 모든 씬 생성 시 이 이미지를 참조 이미지로 넣어서 동일 인물/장소로 유지 (Higgsfield Elements, Kling reference image, RoboNeo 등 어떤 백엔드든 "참조 이미지 입력" 기능이 있으면 동일하게 적용 가능)

### 2. 시놉시스 → 씬 분해
- 대본(시놉시스 한 문단: 주인공/사건/감정변화/전체 길이)을 시작-전개-절정-결말 4단계로 나눈다
- 각 단계를 몇 초짜리 씬 몇 개로 찍을지 정한다 (S.00~S.03 기준 30~60초 = 5~7씬 권장, EP.xx 본편은 씬 수 자유)

### 3. 씬별 카메라 샷 프롬프트 생성
씬마다 아래 4개 섹션을 반드시 순서대로 채운다 (원본 SKILL.md 구조 그대로 채택):

1. **SHOT-BY-SHOT 타임라인**: 각 샷을 `SHOT [N] ([타임스탬프]) — [설명]` 블록으로. EFFECT(주효과+보조효과), 화면 묘사, 카메라 움직임(각도/무빙/렌즈), 속도, 다음 샷과의 전환 방식을 명시
2. **효과 인벤토리**: 전체 씬에서 쓰인 효과를 번호 매겨 나열 (몇 번 쓰였는지, 어느 샷에 나오는지)
3. **밀도 맵**: 3~6초 구간별로 HIGH/MEDIUM/LOW 밀도 표시 (효과 개수 기준)
4. **에너지 아크**: 3막 구조(도입-전개-결말)로 전체 긴장감 흐름 서술. 30초 이하 쇼츠는 2막으로 축약 가능

### 4. 부정문 금지 원칙
"울고 있지 않다" 같은 부정문 대신 "담담한 표정"처럼 원하는 상태를 직접 서술 (AI 영상 생성 모델이 부정문을 반대로 해석하는 경우가 실제로 있음 — 뽀개기 2번 원본 영상에서 확인된 함정)

### 5. 렌더링 백엔드 연결
- 현재 파이프라인 상태: Kling 직접 자동화는 UI 변경으로 붕괴(T033) → 로보네오(RoboNeo) 우회 검증 중(T064)
- 이 스킬은 백엔드에 무관하게 "프롬프트 설계" 단계만 담당 — 실제 생성 호출은 안티의 렌더링 파이프라인(`roboneo_auto.py` 등)에 프롬프트를 넘기는 방식으로 연결

## 창작 원칙 (원본 스킬에서 채택)
- 대비가 임팩트를 만든다: 고밀도-저밀도 구간을 번갈아 배치
- 씬마다 "시그니처 효과"(가장 인상적인 한 장면)를 최소 1개 지정
- 전환도 하나의 샷이다 — 단순 컷이 아니라 연출로 취급
- 모호함보다 구체성: "카메라가 틸트된다"보다 "카메라가 시계방향 15~20도 회전한다"
- 에너지는 반드시 착지한다 — 끝이 흐지부지되면 안 됨

## 뿌리체계 편입 위치
63_youtube_creator 하위, S.00~EP.xx 제작 파이프라인의 "대본 확정 후 ~ 렌더링 착수 전" 단계에 위치.
